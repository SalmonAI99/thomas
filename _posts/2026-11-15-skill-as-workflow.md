As language models' ability thriving, rigid structures will gain less and less advantage compared to loose ontology defined by prompts and skills.

### The bitter lesson

In the artical The bitter lesson, Rich Sutton proposed that researchers in machine learning fields tends to focus too much on some constraining methods or scaffolding which will most possibly not needed as the intelligence of the agent evolve. This is an accurate framing on today's AI agent environment.
https://www.cs.utexas.edu/~eunsol/courses/data/bitter_lesson.pdf

### Early frameworks are too constraint

When GPT3.5 first broke out, we could see lots of work surrounding orchestrating GPT (autoGPT); Langchain also start in this period. Later the constraint is loosened by introducing prompt engineering (i.e. design system prompts to let llm work as instructed) When I am building the Cirdan agent using Langchain, I can still remember gpt4o still struggle following instructions plainly layed out. The system prompt will be like this:

```markdown
- you should do this:
  1.  something
  2.  another thing
- you shouldn't do:
  1.  something
  2.  other things
```

And we chose to design an virtual code navigation tool system. This involves tools like "hover", "go to definition", "display line n to m". Despite verbose system prompts, llm often failed to execute according to plan. Sometimes it hog over something, other times it skip steps. It was such a bad experience developing and performing prompt finetuning.
Most of the time is spent goinging through langfuse trace and inspect tool call logs. Context overflow is also a constant headache.

### Harness and Sandbox

Claude code is probably the first to promote the concept of a harness. I think the concept went viral after some serious long-horizon software systems (ccc) and not long afterward people talks about agent loop (from my point of view they are the same thing, which also correlate with the famous ReAct paper). At this stage, people already tends to not limit the ability of agent and give them full power over the machine. Lots of previous LLM applications become redundant since they have no edge over a bare metal model surrounded with a bash environment. The overal ability of Agents become bounded by not only the underlying model but also the harness surrounding it.
Sandbox appear at this stage as a security layer on top of the operating systems. The core of harness is Agent loop, or ReAct as you like.

### Skills as foundation for workflow

Since model is optimized literally for everything, when some situation sits beyond the model's training dataset, it needs guidance. This is where skills come in. Skill became a new star among developers because of its flexibility and human friendly nature. Don't underestimate this feature. When we build agents, one of the constant scene is how to adjust the tightness of the model. If we give it a rigid structure we may jeopardize its mobility to judge and take actions. At this stage model's ability to follow the instructions have also advanced considerably, if we want it to behave this way it likely will not resist. Workflows purely written with skills gained popularities ([auto research in sleep](https://github.com/wanshuiyin/Auto-claude-code-research-in-sleep/blob/main/README_CN.md)). The popularity of skills also leads to model companies to invest much more to fit this feature. . It is believed that in the days to come, this connection will grow stronger and model's ability to utilize skills will be more authentic.

Creating good skills becomes a must in using harness. Good news is that skills can be auto-generated by llm (meta harness). You either let the llm directly summarize from traces or let it device them zero shot. It is also a natural thing to do for the models. This brings convenience and abstract away boiler plate langchain code just to lead the llm to follow along. The future for development will be: There will be a benchmark, and agent run against it, creating skills as workflows for out of bound scenarios, optimize through iteration. This will keep the developers out of the rogue work of debugging langchain code which could be pain in the ass.

With such a background, lots of previous workflow design becomes replacable. And the fact is they should be replaced in the future, as a byproduct of yet to improve agent capability. This is happening right now and should be finished not long in the future.

### Skill as a service

AaaS naturally emerged after the triving of Agent. As skill begins to replace workflow, we can naturally think of Skill As A Service. The workflow, some edge case operation instructions, all become the service. Nowadays lots of skills are opensource, but there are also tons of service around AI. The competition becomes wheter the agent can handle tasks more efficiently and intelligently. When the underlying model's ability equals, the advantage will be brought by skills.
